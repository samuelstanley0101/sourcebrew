# Recipe Cookbook

A *recipe* is a set of instructions for building, installing, and managing a package. It's conceptually similar to a [formula](https://docs.brew.sh/Formula-Cookbook) in Homebrew, but only for building from source.

## Recipe Standard

*Standard Version 1.0.*

This section defines the standard for how recipes should be defined.

### Definitions

- **Building:** Compiling or otherwise turning source code into an executable or other usable format.
- **Package:** Software that gets built. This can be an application (command-line or desktop) or a library.

### Recipe Contents

Recipes are stored in their own individual directories under the `Recipes` directory. They contain the instructions for building a package, **but not the package code itself**.

While a recipe may contain any number of files with the commands for building a package, the only file required for a recipe is `index.json`, which defines the attributes and commands for a recipe. A `BUILD.md` file with the build instructions written in plain English is also highly encouraged, since it can help maintain the automated build, but it's not required.

The file structure of the `sourcebrew-example` recipe is shown below, which is what a typical recipe might look like.

```txt
sourcebrew-example
├── BUILD.md
├── build.sh
└── index.json
```

### Recipe Definition

Recipes are defined in an `index.json` file, which is the only file *required* for a recipe. You can find an example of a recipe definition in `Recipes/sourcebrew-example/index.json` or in `Recipes/sizeof/index.json`.

Below are the fields in a recipe definition:

*Some descriptions are taken from [Homebrew's Formula Class docs](https://docs.brew.sh/rubydoc/Formula.html).*

```json
{
    "sourcebrew_standard": "[sourcebrew standard version]",
    "name": "[recipe/package name]",
    "desc": "[package description]",
    "homepage": "[package homepage URL]",
    "type": ["[package type]"],
    "recipe_install_command": "(optional) [command to install the recipe]",
    "commands": {
        "clone": "[command to clone the source code]",
        "status": "[command to get source code status]",
        "pull": "[command to pull changes to the source code]",
        "build": "[command to build the source code]",
        "clean": "[command to remove built files]"
    },
    "executables": ["[executables generated by the build command]"],
    "apps": ["[.app packages generated by the build command]"],
    "recipe_version": "[recipe version number]"
}
```

- `"sourcebrew_standard"`: The version of the sourcebrew standard used. Currently there is only one version, so you can just put `"1.0"`.
- `"name"`: The name of the recipe being defined. This **must** be the same as the name of the recipe's directory. Most often this is the same as the name of the package being built.
- `"desc"`: A one-line description of the software being built. Used by users to get an overview of the software and Sourcebrew maintainers. Shows when running `sourcebrew info`.
- `"homepage"`: The URL of the homepage for the software. Used by users to get more information about the software and Sourcebrew maintainers as a point of contact for e.g. submitting patches. Can be opened by running `sourcebrew home`.
- `"type"`: The type(s) of package the recipe builds. There are three types:
  - `"cmd"`: Command-line software.
  - `"app"`: A desktop application, packaged in `.app` format.
  - `"lib"`: A code library *(full specification TBD)*.
- `"recipe_install_command"` *(optional)*: A field to specify a command to run to install the recipe, if needed. If your recipe is programmed using a compiled language, this is where you would put the command to compile it.
- `"commands"`: The distinct functions the recipe must implement for Sourebrew to manage the software. Read the [Recipe Commands](#recipe-commands) section for more details about implementation.
  - `"clone"`: Download the source code for the first time.
  - `"status"`: Find out if there are changes to the source code ready to be pulled. More details about the required format for responses can be found in the [Recipe Commands](#recipe-commands) section.
  - `"pull"` *(optional)*: Pull changes to the source code. If not specified, all pull operations will be performed by deleting the source code and cloning it again.
  - `"build"`: Build the source code. **This should not install the resulting files, only build them**.
  - `"clean"`: Remove any files generated by the `"build"` command from the source code.
- `"executables"`: A list of executable files generated by the `"build"` command which should be accessible to the user. Required if `"type"` is `"cmd"`.
- `"apps"`: A list of `.app` packages generated by the `"build"` command. Required if `"type"` is `"app"`.
- `"recipe_version"`: The version number for the recipe.
